## Available Tools (with metadata)
  - **extract_manifest** [configuration] (cost: very_low, ~1s)
    Extract AndroidManifest.xml data from an APK file. Returns permissions, activities, services, receivers, content providers, and security-relevant manifest attributes (debuggable, allowBackup, usesCleartextTraffic). This should be the FIRST tool called for any new APK investigation.
    Arguments: apk_path: string (required)
    Produces: permissions, high_risk_permissions, exported_components, manifest_flags, package_name
    Confidence: foundational — always required as investigation starting point
  - **scan_permissions** [configuration] (cost: very_low, ~2s)
    Perform deep manifest vulnerability analysis on an APK. Identifies security misconfigurations: debuggable flag, allowBackup, cleartext traffic, exported components without permission protection, and insecure content providers. Use this AFTER extract_manifest when the manifest shows concerning flags or exported components.
    Arguments: apk_path: string (required)
    Produces: manifest_vulnerabilities, debuggable_flag, backup_flag, cleartext_traffic, exported_components_without_protection
    Confidence: identifies manifest-level security misconfigurations
  - **run_apktool** [resources] (cost: low, ~15s)
    Decode an APK using APKTool for deep resource analysis. Analyzes smali code structure (class count, multidex detection), native libraries (.so files by architecture), embedded assets (suspicious .dex/.jar/.bin files), certificates, resource strings, and secondary DEX files. This tool provides evidence that manifest and source code analysis cannot: dropper indicators, obfuscated payloads, native code presence, and resource-level anomalies.
    Arguments: apk_path: string (required)
    Produces: smali_structure, native_libraries, embedded_assets, certificates, resource_strings
    Confidence: detects dropper indicators, obfuscated payloads, native code presence, and resource anomalies that source code analysis misses
  - **run_jadx** [source_code] (cost: medium, ~30s)
    Decompile an APK using JADX and scan the resulting Java source code for suspicious API calls (Runtime.exec, SmsManager, DexClassLoader, etc.), hardcoded secrets (passwords, API keys, backdoor credentials), and crypto weaknesses. Returns structured evidence with signal levels (HIGH/MEDIUM/LOW). Use this when manifest analysis reveals dangerous permissions or you need to understand the code behavior behind a permission.
    Arguments: apk_path: string (required)
    Produces: suspicious_apis, hardcoded_secrets, code_snippets, signal_level_counts
    Confidence: primary source of code-level threat indicators — identifies suspicious API usage, hardcoded secrets, and crypto weaknesses
  - **run_frida** [runtime] (cost: high, ~30s)
    Run Frida-instrumented dynamic analysis on an APK in the Android emulator. Installs the APK, hooks into Runtime.exec, SmsManager, Cipher, URL, Base64, and File operations, then monitors for the specified duration. Returns structured runtime events showing what the app ACTUALLY did when executed. Use this when static analysis reveals dangerous capabilities (e.g., Runtime.exec, SmsManager) and you need to verify if they trigger at runtime.
    Arguments: apk_path: string (required), package_name: string (required), duration_seconds: integer
    Produces: runtime_events, hook_coverage, event_breakdown, instrumentation_status
    Confidence: validates or refutes static capabilities at runtime — the strongest form of evidence
  - **collect_logcat** [runtime] (cost: very_low, ~2s)
    Collect Android logcat output from the emulator, optionally filtered by package name. Returns recent log lines including crashes, ANRs, and security-relevant system warnings. Use this after running Frida or Monkey to capture additional runtime context.
    Arguments: package_name: string, max_lines: integer
    Produces: logcat_lines, error_lines, warning_lines, crash_detection
    Confidence: supplementary — captures crashes, ANRs, and system warnings that Frida hooks miss
  - **run_monkey** [runtime] (cost: high, ~60s)
    Run Android Monkey to generate random UI events (touches, gestures, key presses) in the target application. This exercises code paths that simple launch might not trigger. Use this after Frida shows few events, to force the app through more execution paths and potentially trigger hidden behaviors.
    Arguments: package_name: string (required), event_count: integer
    Produces: events_injected, crashes, anrs, ui_exploration_coverage
    Confidence: exercises code paths that passive observation misses — can trigger hidden behaviors
  - **capture_screenshot** [runtime] (cost: very_low, ~2s)
    Capture a screenshot of the current Android emulator screen. Useful for documenting what the app displays at runtime and detecting suspicious UI patterns (overlay attacks, fake login screens, permission request dialogs). Use this during or after dynamic analysis.
    Arguments: label: string
    Produces: screenshot_image, timestamp
    Confidence: supplementary — visual documentation of runtime state, phishing overlay detection
  - **generate_report** [reporting] (cost: very_low, ~0s)
    Signal that the investigation is complete and generate the final report. Call this when you have gathered sufficient evidence to produce a verdict. You should call this when: (1) all relevant tools have been run, or (2) you have enough HIGH-confidence evidence for a clear verdict, or (3) further investigation would not change the conclusion. Do NOT call this prematurely — ensure at minimum that manifest and source code analysis are complete.
    Arguments: reasoning: string (required)
    Produces: investigation_complete_signal
    Confidence: terminal action — signals that sufficient evidence has been gathered for a verdict
